# Стратегия команды на CTF Cup Quals 2026

## Исходные данные

В команде семь участников:

| Участник | Основная область | Дополнительные навыки |
|---|---|---|
| greek | web | forensics на среднем уровне |
| DRAK0NN | forensics | web на среднем уровне |
| lldark | web | reverse на среднем уровне |
| Lera | web | forensics на среднем уровне |
| Gromka | web | forensics на среднем уровне |
| Candy | reverse | нет заявленных дополнительных категорий |
| ℂаnnaβ∫$ | web | forensics, reverse на среднем уровне |

Команда сильна в web, имеет одного профильного reverse и одного профильного forensic. В таблице нет участников с заявленной специализацией pwn или crypto. Исторический контекст показывает, что CTF Cup регулярно предлагает сложные pwn, crypto, reverse и forensic-задачи. Значит, команда не должна распределять людей равномерно по категориям. Она должна быстро собрать дешёвые баллы в web/beginners/forensics, а затем концентрироваться на задачах, где AI и совместная работа закрывают дефицит pwn/crypto.

## Цели

1. Забрать простые и средние web-задачи в первые часы.
2. Не потерять beginners, warmup, OSINT и PPC из-за отсутствия владельца.
3. Выделить Candy время без постоянных переключений на reverse.
4. Использовать DRAK0NN как владельца forensic-пайплайна.
5. Создать две временные ударные группы для pwn и crypto.
6. Не держать более двух человек на одной гипотезе дольше 30 минут без новых данных.

## Роли

### Координатор

Рекомендуемый координатор: **greek**. Причина: профильный web совпадает с самой широкой компетенцией команды, а опыт в forensics помогает оценивать задачи за пределами web.

Координатор:

- ведёт общую доску задач;
- назначает владельца и ревьюера;
- следит за временем последнего прогресса;
- переключает людей между задачами;
- утверждает использование дорогих моделей;
- проверяет, что флаг и способ решения зафиксированы.

Координатор не должен одновременно вести больше одной сложной задачи.

### Владельцы направлений

| Направление | Владелец | Резерв |
|---|---|---|
| Web | greek | Lera, Gromka, lldark, ℂаnnaβ∫$ |
| Reverse | Candy | lldark, ℂаnnaβ∫$ |
| Forensics | DRAK0NN | Lera, Gromka, greek, ℂаnnaβ∫$ |
| Pwn | Candy | lldark |
| Crypto | ℂаnnaβ∫$ | greek |
| PPC / Misc / OSINT | Lera | Gromka |
| Инфраструктура и общая база знаний | Gromka | DRAK0NN |

Назначение владельца pwn не означает, что Candy уже силён в pwn. Reverse даёт лучшую базу для чтения бинарников. Владелец crypto должен использовать AI и быстро передавать задачу, если не может сформулировать математическую модель.

## Работа до соревнования

### За 2–3 недели

1. Поднять общий Git-репозиторий с каталогами `knowledge/`, `tasks/`, `scripts/`, `templates/`.
2. Установить одинаковые версии Python, pwntools, SageMath, GDB/pwndbg, Ghidra, Volatility, Wireshark, Docker и browser tooling.
3. Провести пять тренировок по историческим задачам:
   - web parser differentials и SSRF-chain;
   - browser/CSP;
   - Linux pwn и kernel basics;
   - custom VM/reverse;
   - memory/firmware forensics.
4. На каждой тренировке использовать тот же task lifecycle, что и на соревновании.
5. Проверить лимиты AI, API keys и резервный доступ до начала CTF.

### За день

- Проверить VPN, Discord/Matrix, Git, Docker, виртуальные машины и часы системы.
- Очистить AI-чаты от нерелевантного контекста.
- Создать шаблон карточки задачи.
- Зафиксировать бюджет моделей и ответственного за расходы.
- Отключить автоматическую отправку секретов, токенов и флагов во внешние сервисы, если правила соревнования это запрещают.

## Первые 30 минут соревнования

Каждый участник открывает 2–3 задачи из своей области и заполняет карточку:

```markdown
# Название

- Категория:
- Баллы / solves:
- Владелец:
- Ревьюер:
- Статус: triage | active | blocked | solved
- Выданные файлы:
- Сервис:
- Предполагаемая техника:
- Похожие исторические задачи:
- Дешёвая проверка гипотезы:
- Последний прогресс:
- Следующий шаг:
```

Оценка задачи:

| Критерий | 0 | 1 | 2 |
|---|---:|---:|---:|
| Совпадает с навыками | нет | частично | да |
| Есть исходники | нет | часть | полный комплект |
| Понятна первая гипотеза | нет | слабая | проверяемая |
| Есть исторический аналог | нет | похожий | почти прямой |
| Ожидаемое время | >3 ч | 1–3 ч | <1 ч |

Сначала брать задачи с суммой 7–10. Задачи с суммой 0–3 оставить до появления дополнительной информации.

## Волны решения

### Волна 1: первые баллы

- Пять web-участников делятся между web, beginners, OSINT и PPC.
- DRAK0NN проверяет forensic.
- Candy проверяет reverse и простые pwn.
- На одной задаче работает один владелец и один короткий AI-сеанс.

Цель: закрыть понятные задачи и не пропустить задания с высокой solve-rate.

### Волна 2: задачи средней сложности

Формируются пары:

- web source audit: greek + Lera;
- browser/parser chain: lldark + Gromka;
- forensics: DRAK0NN + ℂаnnaβ∫$;
- reverse/pwn: Candy + lldark;
- crypto/PPC: ℂаnnaβ∫$ + greek.

В паре один человек строит гипотезу, второй проверяет код, документацию и вывод AI. Через 45 минут роли меняются.

### Волна 3: сложные цепочки

На сложной задаче работают до трёх человек:

1. исследователь строит модель уязвимости;
2. исполнитель пишет exploit/solver;
3. ревьюер проверяет предположения и воспроизводимость.

Дорогую модель подключать после подготовки краткого пакета контекста: условие, дерево файлов, ключевые фрагменты кода, проверенные гипотезы и точный вопрос.

## Правило остановки

Перевести задачу в `blocked`, если за 30 минут не появилось ни одного из результатов:

- новая подтверждённая гипотеза;
- воспроизводимый crash или oracle;
- новая утечка;
- расшифрованный формат;
- минимальный proof of concept;
- сокращение пространства поиска.

Перед переключением владелец записывает проведённые тесты и причины отказа от гипотез. Следующий участник не должен повторять те же действия.

## Приоритеты по историческим данным

### Высокий приоритет

- различия parser/WAF/backend;
- SSRF во внутренние Redis, Celery, Elasticsearch, CDP и PDF-сервисы;
- CSP bypass и browser bot;
- deployment topology из Docker Compose;
- Windows memory/Registry и firmware;
- custom VM и runtime patching.

### Зона риска

- kernel pwn;
- Rust unsoundness;
- сложная теория чисел и ECC;
- heap exploitation;
- multi-architecture reverse.

На задачах зоны риска команда сначала ищет исторический аналог в `context.md`, затем привлекает AI. Если через 60–90 минут нет рабочего primitive, координатор снижает приоритет.

## Контроль сдачи

Перед отправкой флага:

1. Второй человек воспроизводит решение или проверяет solver.
2. Команда сохраняет команду запуска и зависимости.
3. В карточку записываются root cause и exploit chain.
4. Флаг отправляется один раз после проверки формата.
5. После solve участник добавляет краткое знание в базу и переходит к следующей задаче.

## Метрики

Координатор раз в час фиксирует:

- число solved задач;
- число active и blocked задач;
- людей без активной задачи;
- расходы AI за час;
- задачи без ревьюера;
- категории, в которых команда ещё не провела triage.
